# Phase 8 software implementation — 2026-11-05

Implemented the final React/TypeScript clinician workspace using Vite, React Router and types generated from the Go OpenAPI contract. Locked dependencies and a stale-type check are included. Docker now performs a clean frontend install/build before embedding static assets in the Go binary; Node is not part of the runtime. Host Go package checks require the frontend build first. CI ordering and the integration-runner diagnostic reflect this.

Migrated actual rendering/forms to React components for password login/activation, dashboard, patients/labs/sharing/archive, assessment editing, saved results/replay/export/comparison, source evidence, document upload/version/indexing, candidate preparation/edit/review, own-password change and staff administration. Browser key entry and the imperative client are no longer served. Setup/demo scripts retain explicit API service-key support; the account setup CLI can explicitly renew an existing account's activation into a new private file.

Stable browser routes restore on direct navigation/reload. Go only falls back to the browser shell for browser paths; unknown API/health/assets stay non-HTML 404s. Added authorised single-observation lookup for assessment links independent of list pagination. New administrator endpoints provide bounded hash-checked audit summaries without clinical payloads, streaming whole-chain verification with an observed head, and actual source/rule/model-configuration status. The legacy full-audit endpoint remains compatible for scripts.

Navigation guards protect dirty forms, including back navigation; browser reload/close uses beforeunload. Each form owns a dirty flag, successful saves clear it synchronously before navigation, and Escape/Keep editing preserves input. Session/route changes cancel obsolete requests; logout/password changes/account-session changes clear other same-browser tabs through transient broadcasts. Revocation clears protected data on the next authenticated request. No persistent browser patient/credential cache is used. Evidence replies cannot repopulate a changed query. Candidate edits fix source identity/digest; new source/passage choices reset candidate fields. Clinical outputs and calculations remain server-owned.
